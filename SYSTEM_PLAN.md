# План системы: путешествие «от двери до двери»

Набросок, чтобы не забыть замысел целиком. Решения приняты в интервью (grill-me) 2026-10-06; то, что ещё не решено, собрано в конце.

## Идея

Человек говорит «хочу поехать…», агент разговаривает с ним, понимает предпочтения, предлагает варианты и собирает **полный маршрут от двери дома до двери отеля и обратно**: такси, перелёт, поезд, трансфер, жильё, всё по времени. Потом сопровождает в пути и перепланирует, если что-то сдвинулось. В итоге система ещё и заказывает всё сама (с возможностью отключить).

## Два слоя

| Слой | Что делает | Статус |
|---|---|---|
| **Скилл `trip-planner`** (Claude Code) | Диалог, поиск, сборка маршрута, проверка, режим «в пути». Ничего не оплачивает: выдаёт ссылки | v1, делаем сейчас |
| **Система** (отдельный сервис) | Автозаказ по готовому маршруту, слежение за рейсами, уведомления первым | позже |

Граница между ними — файл `itinerary.json`: скилл его пишет, система читает и переводит шаги в `booked`.

## Архитектура скилла

Гибрид «оркестратор + исполнители» и «оценщик + доработка»:

```
Главный агент (говорит с пользователем, по-русски)
 ├─ 1. Диалог → бриф
 │     · профиль из ~/.search-travel/profile.md, уточнить, а не спрашивать заново
 │     · 3–5 вопросов за раз, затем 2–3 контрастных варианта, реакция = предпочтения
 ├─ 2. Параллельно субагенты-исполнители:
 │     перелёт · жильё · поезда · трансферы туда · трансферы обратно
 ├─ 3. Сборка маршрута по времени
 ├─ 4. Проверка правилами (без модели): стыковки, запасы, бюджет
 ├─ 5. Судья: проверка всего маршрута против брифа → до 2 доработок
 └─ 6. Пользователю: 2–3 маршрута «дешевле / быстрее / комфортнее» + рекомендация
```

- Инструкции исполнителей и судьи лежат файлами внутри папки скилла, главный агент передаёт их субагентам. Одна установка: `npx skills add`.
- Субагент не может говорить с пользователем, поэтому весь диалог ведёт только главный агент.
- Текст скилла на английском, общение с пользователем на русском.

### Режим «в пути»

Пользователь пишет «заказал такси» или «рейс задержали». Скилл читает `itinerary.json`, отмечает пройденные шаги, показывает следующий, при сдвиге перепланирует оставшиеся шаги (перенести трансфер, предупредить отель о позднем заезде). Claude Code отвечает только на сообщения, сам первым не пишет, поэтому это работа системы.

## Правила по умолчанию (пользователь может изменить)

- Аэропорт: за 3 ч до международного рейса, за 2 ч до внутреннего.
- Вокзал: за 30 мин.
- Такси: +20% к времени поездки.
- После прилёта: 45 мин на выход, 75 мин, если сдавать багаж.

## Судья: маршрут готов, когда

1. Каждый шаг соответствует брифу: даты, бюджет, жёсткие ограничения.
2. По времени нет разрывов и нахлёстов, запасы соблюдены.
3. У каждой цены есть ₽ и исходная валюта, ссылка, время проверки.
4. Маршрут непрерывен от двери до двери в обе стороны.
5. Варианты действительно различаются по своему критерию.

Не прошло после 2 доработок → честно сказать пользователю, какой пункт не выполнен.

## Источники (v1: поиск + ссылка)

| Участок | Источник | Как оформляется |
|---|---|---|
| Перелёт | Kiwi MCP `mcp.kiwi.com` (бесплатно, без ключа) | ссылка на покупку |
| Жильё | веб-поиск | ссылка Booking |
| Поезда | веб-поиск | ссылка Omio / Trainline / 12Go |
| Такси дом ↔ аэропорт | оценка «≈» | ссылка в приложение Uber/Bolt с заполненными адресами, «в один клик» |
| Трансфер аэропорт ↔ отель | Welcome Pickups / Kiwitaxi | заранее, фиксированная цена |
| Курс ₽ | Frankfurter MCP (`providers=CBR`), запасной — XML ЦБ РФ | курс ЦБ на сегодня, «≈» + цена в валюте рядом |

Все ссылки собираются в одном месте скилла, чтобы позже добавить партнёрский ID (Travelpayouts, Booking) одной правкой.

## Файлы

```
~/.search-travel/profile.md        профиль: класс, места, жильё, бюджет, аллергии…
                                    НЕ хранить: паспорт, карты, точный домашний адрес
trips/<дата>-<город>/
  brief.md                          договорённости из диалога
  itinerary.md                      маршрут для человека
  itinerary.json                    маршрут для машины (договор с системой)
```

Набросок шага в `itinerary.json`:

```json
{
  "id": "step-1",
  "type": "taxi | flight | train | transfer | stay",
  "from": "…", "to": "…",
  "start": "2026-11-01T05:40:00+03:00",
  "end":   "2026-11-01T06:30:00+03:00",
  "price": { "amount": 25, "currency": "EUR", "rub": 2400, "rate_source": "CBR", "checked_at": "…" },
  "link": "…",
  "status": "planned | booked | done | changed"
}
```

## Система (следующий этап)

- **Автозаказ** по `itinerary.json` с переключателем «вкл/выкл». Подтверждение перед каждой оплатой.
- **Перелёты и отели**: Duffel (единственный самостоятельный вариант с настоящими билетами), Duffel Stays. Для боевого режима нужна проверка компании; страны под санкциями исключены.
- **Оплата**: Duffel Links (готовая страница оплаты), либо карта через API (только 22 страны).
- **Такси**: бронирование через API у Uber только после одобрения, у Bolt публичного API нет. Пока «в один клик» через ссылку.
- **Слежение и уведомления**: статус рейса, задержки, push пользователю, автоматическая перепланировка.
- **Отели, поезда, трансферы с настоящим бронированием**: только по договорам (Booking Demand, Expedia Rapid, Trainline, Omio Booking API, GetTransfer).

## Этапы

1. **v1 скилл**: диалог, профиль, поиск, сборка, проверка, `itinerary.md/json`.
2. **v1.1**: режим «в пути».
3. **Система, шаг 1**: Duffel на тестовом ключе, автозаказ перелётов и отелей.
4. **Система, шаг 2**: слежение за рейсами, уведомления, бронирование такси/трансферов.
5. Партнёрские ID в ссылках.

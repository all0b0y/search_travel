# План: trip-planner и система

Решения приняты в интервью 2026-10-06. Решение, которое нужно поменять, сначала согласуй с владельцем репозитория.

## Замысел

Пользователь говорит, куда хочет. Агент в диалоге собирает **бриф**, ищет варианты и собирает **маршрут от двери до двери**: дом → такси → перелёт/поезд → трансфер → отель и обратно, всё по времени. Затем сопровождает **в пути**.

Два слоя, граница между ними — **договор** `itinerary.json`:

- **Скилл `trip-planner`** (Claude Code) пишет договор: диалог, поиск, сборка, проверка, «в пути». Оплачивает пользователь сам, по ссылкам.
- **Система** читает договор: бронирует, следит за рейсами, пишет пользователю первой. Её устройство описано в [`docs/system.md`](docs/system.md); читать на этапах 3–4.

## Этапы

1. **Скилл v1.** Переименовать `skills/search-travel` → `skills/trip-planner`, переписать по разделу «Скилл» ниже (через `writing-for-agents`), обновить README. Готово, когда на запросе «Берлин → Лиссабон, 2 взрослых, 3 ночи в ноябре, до 150 000 ₽» скилл провёл диалог, создал папку поездки с тремя файлами, каждый шаг договора заполнен по схеме, судья принял маршрут, пользователь получил 2–3 маршрута.
2. **«В пути».** Готово, когда на сообщение «рейс задержали на 2 часа» скилл сдвинул все зависимые шаги, обновил их `status`, и цепочка снова проходит правила по времени.
3. **Система: автозаказ** перелётов и жилья на тестовом ключе Duffel. Готово, когда договор из этапа 1 доходит до `booked` на всех шагах `flight` и `stay`.
4. **Система: слежение** за рейсами, уведомления, такси и трансферы.
5. **Партнёрские ID** в ссылках.

После этапа 1 источник истины для разделов «Скилл» — файлы скилла. Удали эти разделы отсюда и оставь ссылку на `skills/trip-planner/`.

## Скилл

### Поток

```
Главный агент: единственный, кто говорит с пользователем
 1. Диалог → бриф
 2. Исполнители параллельно: перелёт · жильё · поезда · трансферы туда · трансферы обратно
 3. Сборка маршрута по времени
 4. Проверка правилами, без модели: стыковки, запасы, бюджет
 5. Судья: маршрут против брифа, до 2 доработок
 6. Пользователю: 2–3 маршрута «дешевле / быстрее / комфортнее» + рекомендация с учётом профиля
```

- Инструкции исполнителей и судьи лежат файлами в папке скилла, главный агент передаёт их субагентам. Скилл ставится одной командой `npx skills add`.
- Текст скилла на английском, с пользователем — по-русски.

### Бриф и профиль

- Бриф: откуда, даты или окно гибкости, путешественники (возраст детей), бюджет в ₽, жёсткие ограничения. Диалог: 3–5 вопросов за раз, затем 2–3 контрастных варианта, реакция на них выявляет предпочтения.
- Профиль `~/.search-travel/profile.md`: класс, места, тип жилья, бюджет, аллергии. Скилл уточняет профиль, а не спрашивает заново. Вместо домашнего адреса хранится район или ближайший аэропорт; точный адрес, паспорт и карта спрашиваются в той поездке, где нужны, и остаются только в ней.

### Временные запасы

Пользователь может изменить любой.

| Где | Запас |
|---|---|
| Аэропорт, международный рейс | 3 ч до вылета |
| Аэропорт, внутренний рейс | 2 ч |
| Вокзал | 30 мин |
| Такси | +20% к времени поездки |
| После прилёта | 45 мин, со сдачей багажа 75 мин |

### Судья

Маршрут принят, когда выполнены все пункты:

1. Каждый шаг соответствует брифу: даты, бюджет, жёсткие ограничения.
2. По времени нет разрывов и нахлёстов, запасы соблюдены.
3. У каждой цены есть ₽, исходная валюта, ссылка и время проверки.
4. Маршрут непрерывен от двери до двери в обе стороны.
5. Варианты различаются по своему критерию.

После 2 доработок пользователь получает маршрут с явным списком невыполненных пунктов.

### Источники

Факты о сервисах (доступ, цены, ограничения) собраны в [`docs/sources.md`](docs/sources.md): читать, когда выбираешь или подключаешь источник.

| Участок | Источник | Что получает пользователь |
|---|---|---|
| Перелёт | Kiwi MCP | ссылка на покупку |
| Жильё | веб-поиск | ссылка Booking |
| Поезда | веб-поиск | ссылка Omio / Trainline / 12Go |
| Такси дом ↔ аэропорт | оценка цены «≈» | заказ в один клик: ссылка в приложение такси с заполненными адресами; заказ такси запускает режим «в пути» |
| Трансфер аэропорт ↔ отель | Welcome Pickups / Kiwitaxi | заранее, фиксированная цена |
| Курс ₽ | курс ЦБ через Frankfurter MCP | «≈ X ₽» и цена в исходной валюте рядом |

Все ссылки строятся в одном месте скилла, чтобы партнёрский ID добавлялся одной правкой.

### Файлы поездки

```
trips/<дата>-<город>/
  brief.md          бриф из диалога
  itinerary.md      маршрут для человека
  itinerary.json    договор
```

Шаг договора:

```json
{
  "id": "step-1",
  "type": "taxi | flight | train | transfer | stay",
  "from": "…", "to": "…",
  "start": "2026-11-01T05:40:00+01:00",
  "end":   "2026-11-01T06:30:00+01:00",
  "price": { "amount": 25, "currency": "EUR", "rub": 2400, "rate_source": "CBR", "checked_at": "…" },
  "link": "…",
  "status": "planned | booked | done | changed"
}
```

### «В пути»

Пользователь пишет в сессию: «заказал такси», «сел в самолёт», «рейс задержали». Скилл читает договор, отмечает пройденные шаги `done`, показывает следующий и при сдвиге перепланирует оставшиеся: переносит трансфер, предупреждает отель о позднем заезде. Claude Code отвечает только на сообщения пользователя; написать первым умеет только система.

## Открытые вопросы

- Можно ли в ссылке Uber задать время подачи; как устроены ссылки Bolt.
- Страна и форма регистрации системы: от неё зависит доступ к Duffel, Booking, Expedia (см. `docs/sources.md`).

# Архитектура: быстрый путь + глубокий путь

Схема сделана по `search_travel_arch.pdf` (вариант команды) и по коду в ветках `main` и `guide`. Решения — `AGENT_PLAN.md` № 27–35 (интервью 2026-10-28).

Одна строка: **человек пишет → код сразу собирает лучший вариант → если вариант очевидно подходит, отвечаем за 2–4 с; если нет — открытая модель думает до 30 с (шаги и шутки видны), зовёт те же инструменты → код проверяет каждую цифру → человек доходит до корзины и сам оплачивает → после оплаты агент пишет первым и принимает жалобы.**

Метки: `[есть]` — работает в коде, `[дораб]` — есть, нужно доработать, `[новое]` — строим.

## 2. Диспетчер: fast или deep

Обычная функция на Python (`agent/router.py`). На входе — факты о ходе и результат шага 3, на выходе `fast | deep` с причиной в трассе.

```
кнопка                                          → fast   (до диспетчера не доходит)
намерение «жалоба», «после покупки», «справка»  → fast   (свой маршрут, без планировщика)
первый ход сессии                               → fast   (решение 30)
человек повторяет просьбу (то же, что прошлый ход) → deep (прошлый ответ не попал)
шаг 3 ничего не собрал / всё дороже бюджета /
  ослабил требование человека                   → deep   (нужен компромисс)
правка ровно одного простого поля               → fast   («на 2 дня позже», «с собакой»)
серая зона → Jev: «есть подтекст или компромисс?», «хватает ли данных без рассуждения?»
  subtext > порог или enough < порог            → deep
  Jev недоступен                                → deep   (лучше подумать)
```

Пороги лежат в `rules.json` (`router.*`), подбираются на размеченных ходах (см. план, W2).

## 3. Инструменты (общие для обоих путей)

| Инструмент | Что делает | Где |
|---|---|---|
| `rebuild` | пересобрать поездку с другими условиями брифа | `guide.py` [есть] |
| `find_savings` | рычаги экономии с ценой каждого: дни, ночи, отель, пересадка/поезд, похожие места | `guide.py` [есть] |
| `check_road` | прямые / с пересадкой / поезд для пары городов и дат | `guide.py` [есть] |
| `find_destinations` | направления под желания, бюджет, месяц, транспорт | `guide.py` [есть] → + личные сигналы и скидки [дораб] |
| `place_info` | достопримечательности, расстояния, климат, лучшее время, условия отеля | `guide.py` [есть] |
| `compare` | 2–3 варианта рядом | `guide.py` [есть] |
| `find_deals` | реальные скидки мока на направления и даты | [новое] |

Под ними — мок Островка по MCP (отели, перелёты, ЖД, трансферы, корзина, заказ, insights, **скидки, обращения** [новое]) и открытые данные (направления, POI, районы, климат, аэропорты, маршруты). Мок заменяется настоящим API Островка без смены остального.

## 4. Фоновый контур: после оплаты

```
 оплата ──► ПЛАНИРОВЩИК СООБЩЕНИЙ (код, outbox в БД, часы подменяемые)
              │  за 2 дня до выезда  → «Ух, через пару дней Калининград!» + погода + что взять / время заселения
              │  2-й день поездки    → «Как отдыхается?»
              │  день после возврата → «Поделитесь впечатлениями?» → оценка + текст → отзыв
              │  правила: тихие часы по местному времени, ≤ 1 сообщения в день, «не пишите мне» → отписка
              ▼
           ЧАТ: сообщение в сессию + событие в поток (SSE) / опрос входящих

 текст «у нас проблема…» ─► понимание: намерение «жалоба»
              ▼
           ОБРАЩЕНИЕ (код): какой заказ и позиция, что случилось, срочность (правила)
              │  срочное (не заселяют, отменили рейс, нет трансфера) → сразу предложить,
              │  что агент может сделать сам (другой отель на сегодня, другой рейс)
              ▼
           мок: support_create_ticket → номер, срок ответа ─► КОМПАНИЯ: входящие + webhook
              ▼
           ответ: номер обращения и срок, без шуток, без обещаний компенсации
           смена статуса обращения → проактивное сообщение человеку
```

## 5. Модели

| Роль | Модель | Когда |
|---|---|---|
| Понимание (шаг 1) | DeepSeek V4.1 Flash, размышление выкл. | каждый текстовый ход |
| Текст быстрого пути (5a), напоминания, ответ на жалобу | DeepSeek V4.1 Flash, размышление выкл. | fast-ходы, фон |
| Планировщик (5b) | открытая модель с размышлением (выбор замером, решение 28) | deep-ходы |
| Запасной планировщик | DeepSeek V4.1 Flash с размышлением | основной недоступен / не уложился |
| Диспетчер, серая зона | Jev `typesafe/jev-1.13` | спорные ходы, ≈ 0,3 с |
| «Пользователь» в тестах | Sonnet 5.5 (Claude Code) | только evals |
| Судья в тестах | Opus (субагенты) | только evals |

Все модели продукта — с открытыми весами, вызов через OpenRouter, провайдер закреплён (`allow_fallbacks: false`), фактические модель и провайдер пишутся в трассу.

### 6.2 Кто что читает

| Данные | Реальность | Кто читает | Для чего |
|---|---|---|---|
| Направления, POI, районы, климат | реальные | конвейер, `place_info`, `find_destinations` | куда, где жить, когда хорошо |
| Аэропорты, маршруты | реальные | `check_road`, поиск | есть ли дорога |
| Отели (имя, место, тип) | реальные | поиск отелей | что показываем |
| Цены, наличие, расписания, политики | синтетика, детерминированная | мок | цифры в карточках |
| Спрос и сезонность (`insights`) | синтетика, k ≥ 20 | допущения, первый ход | «что обычно берут в ноябре из Москвы» |
| Скидки (`deals`) | синтетика [новое] | `find_deals`, ранжирование направлений | «я ещё и скидочку нашёл» — только при наличии |
| Профиль, путешественники | рантайм | допущения | город, состав, возраст на оформлении |
| Прошлые заказы | рантайм + сид для тестов [дораб] | допущения, первый ход | бюджет, класс отеля, транспорт, «где уже был» |
| Просмотры | рантайм + сид для тестов [новое] | первый ход вернувшегося | «а может, махнём в Калининград?» |
| Обращения, отзывы | рантайм [новое] | компания; отзывы — в insights обезличенно | жалобы и впечатления |

### 6.3 Что реально можно достать из приложения Островка (за пределами демо-данных)

Для разговора с жюри и с Островком: какие сигналы есть у настоящего сервиса и что агент с ними сделает.

| Сигнал в приложении | Что даёт агенту | У нас сейчас |
|---|---|---|

# Система (этапы 3–4 плана)

Отдельный сервис поверх скилла `trip-planner`. Вход — договор `itinerary.json` из папки поездки (схема шага — в [`SYSTEM_PLAN.md`](../SYSTEM_PLAN.md)). Система меняет только поле `status` и добавляет данные брони; маршрут перестраивает скилл.

## Автозаказ (этап 3)

- Переключатель на пользователя: автозаказ включён / выключен. Выключен — пользователь бронирует по ссылкам, как в v1.
- Перед каждой оплатой — подтверждение пользователя с суммой в ₽ и в валюте.
- Перелёты и жильё: Duffel и Duffel Stays. Начать на тестовом ключе; боевой режим требует KYC компании (см. `docs/sources.md`).
- Оплата: Duffel Links (готовая страница оплаты) или карта через API, где страна это позволяет.
- Шаг `planned` → `booked` с номером брони; при отказе сервиса — `changed` и сигнал скиллу перепланировать.

## Слежение и уведомления (этап 4)

- Статус рейсов и поездов; задержка → пересчёт зависимых шагов той же логикой, что режим «в пути» в скилле.
- Push пользователю первым: «через 20 мин выходить», «рейс задержан, трансфер перенесён».
- Такси и трансферы с настоящим бронированием — после одобрения Uber / Welcome Pickups / GetTransfer; до тех пор — ссылка в один клик.
- Отели, поезда, трансферы с бронированием через API — по договорам (Booking Demand, Expedia Rapid, Trainline, Omio Booking API).

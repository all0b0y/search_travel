# evals — track agent evaluation (AGENT_PLAN.md section 10)

| Path | What |
|---|---|
| `cases/*.json` | 40 level-2 phase cases (one card call + assertions). Generated by `python -m evals.authoring.cases_v0` (hand-authored inputs in the exact "Card inputs" shape until `evals.build_inputs` exists). |
| `scenarios/*.json`, `holdout/*.json` | 25 + 10 level-3 scenarios (persona, hidden facts, `must` predicates). `python -m evals.authoring.scenarios_v0`. |
| `schemas/` | case, scenario, persona reply and judge verdict schemas. |
| `card_inputs.py` | binding card-input key sets and shapes (`validate_card_input`). |
| `assertions.py` | level-2 assertion types + named predicates. |
| `predicates.py` | level-3 `must` predicates on the final session / cart / order. |
| `render_ui.py` | Response → screen text with click refs (`[Q1.2]`, `[C1.3]`, `[D1]`, `[V2]`, `[A3]`). |
| `persona.py` | `ClaudeCodePersona` (Sonnet 5.5 via `claude -p`, cwd outside the repo), `FakePersona`, `ButtonPersona`. |
| `skills/persona/SKILL.md`, `skills/judge/SKILL.md` | persona system prompt (`{{scenario}}` placeholder) and the Opus judge rubric. |
| `run.py`, `report.py` | runner and reports (thresholds of decision 16, judge merge, compare). |
| `testing/` | `fake_claude` executable, `FakeEngine`, dry-run card backend. |
| `images/` | 4 Wikimedia Commons images, credits in `images/SOURCES.md`. |

## Commands

```bash
# offline pipeline checks
.venv/bin/python -m evals.run --level 2 --dry-run
.venv/bin/python -m evals.run --level 3 --dry-run            # FakeEngine + ButtonPersona

# live (orchestrator only): DeepSeek Flash through OpenRouter, key from .env
.venv/bin/python -m evals.run --level 2 --model flash --parallel 8
.venv/bin/python -m evals.run --level 3 --set main --flags stage1 --model flash --parallel 3
.venv/bin/python -m evals.run --level 3 --set holdout --flags stage1 --model flash --parallel 3

# judge: Opus subagents apply skills/judge/SKILL.md to <run>/judge/<id>.md -> <id>.verdict.json
.venv/bin/python -m evals.report --merge-judge evals/runs/<run>
.venv/bin/python -m evals.report --compare evals/reports/<A>.json evals/reports/<B>.json
```

Run dirs (`evals/runs/<ts>-L<level>-<set>`, gitignored) hold `level2.jsonl` / `level3.jsonl`
(one line per case run / per turn, with request, response and debug), `scenarios.jsonl`,
`judge/` packets, `summary.json`; live runs also isolate `ostrovok_state.sqlite`, `sessions.sqlite`
and `profiles.sqlite` there. Reports: `evals/reports/<ts>-L<level>-<set>.json|.md` (dry runs:
`<run>/reports/`).

Metric definitions (level 3): touches = the start message + every persona text or click until a
response holds a cart (or order) with a hotel and a flight/train (per the brief's `scope`);
model calls per turn = `debug.calls` entries with a `card`; Jev fallback = `debug.jev` entries
with `fallback: true`, `ok: false` or `answers: null`; fallback-card turns = a `present.fallback`
call or stage; connection errors = blocking issues of `agent.checks.check_variant` on the final
(chosen) variant + blocking cart/order issues.

# search_travel — поездка от двери до двери

Агент планирует поездку целиком: от двери дома до двери отеля и обратно. Такси, перелёт или поезд, трансфер, жильё — всё по времени, с ценой в рублях и ссылками для бронирования. Потом сопровождает в пути: задержали рейс — сдвигает трансфер или переключает на запасной вариант.

Ядро — скилл для [Claude Code](https://claude.com/claude-code), который каждый ход отвечает одним JSON. Система поверх него — веб-страница и API: хранит профиль и сервисы пользователя, показывает ответы, принимает события поездки.

## Что умеет

- **Диалог вместо формы.** Агент уточняет даты, бюджет, ограничения и сколько пользователю стоит час в дороге; к каждому вопросу — рекомендованный ответ.
- **Свои сервисы.** Пользователь сам выбирает, где искать билеты и жильё и чем заказывать такси. Агент выясняет доступ к каждому (MCP-сервер, открытый API, API по ключу или только сайт), говорит, чего не хватает, и даёт ссылки, где это получить. Без сервиса — ищет сам и даёт ссылки.
- **Три маршрута:** дешевле, быстрее, комфортнее. У каждого — итог от двери до двери в ₽ по курсу ЦБ, часы в пути и цена с учётом времени пользователя («быстрее на 48 мин за +26 600 ₽ — при вашей цене часа это не окупается»).
- **Проверка без модели.** Скрипт проверяет непрерывность маршрута, запасы времени (3 ч до международного рейса, выход из аэропорта, +20% к такси), бюджет и даты, считает итоги. Затем отдельный агент-судья проверяет то, что скрипту не видно.
- **План Б** для рискованных стыковок рейс/поезд → рейс/поезд.
- **Календарь** `.ics` с напоминаниями и **страница маршрута** — готовый HTML, чтобы отправить попутчикам.
- **В пути.** «Рейс задержали на 2 часа» → сдвинутые трансферы, переход на план Б, предупреждение о позднем заезде.
- **Гибкие даты** (самый выгодный сдвиг ± N дней), **встреча группы** из разных городов в одном отеле, **поездка по картинке** (фото или ссылка → направление).

## Быстрый старт

Нужен Python 3.11+. Зависимостей нет.

```sh
python3 -m system.server --demo
# → http://127.0.0.1:8000
```

Демо-режим прокручивает тестовую поездку Берлин → Лиссабон по тому же договору, что и настоящее ядро: без сети и без затрат, данные выдуманы (об этом сказано на странице). События «Пройдено / Задержка / Отменено» в нём обрабатывает настоящий скрипт.

С настоящим ядром:

```sh
claude            # один раз: войти в Claude Code
python3 -m system.server
```

Ход стоит порядка $0,1–1,3 и занимает от 15 секунд до 2 минут: дороже всего ход, где ищутся и проверяются маршруты.

## Как устроено

```
Пользователь ⇄ страница ⇄ system/ (API, профиль, сервисы, ключи)
                               │  claude -p <запрос JSON> --json-schema … --resume <сессия>
                               ▼
                 Claude Code + skills/trip-planner  →  один JSON-ответ за ход
                    ├─ исполнители: перелёты · жильё · поезда · трансферы
                    ├─ scripts/trip.py: рубли, итоги, стыковки, календарь, страница
                    └─ судья
```

Один ход ядра:

1. **Подключения** — какими сервисами искать, что для них нужно (ответ `setup`).
2. **Бриф** — недостающие решения пользователя (ответ `questions`); без направления — варианты, куда поехать (`options`).
3. **Поиск** — исполнители параллельно ищут основные участки, затем трансферы под каждый маршрут.
4. **Сборка и проверка** — `trip.py finalize`, судья, до двух доработок.
5. **Ответ** — `itinerary` с тремя маршрутами; в пути — `update` с изменениями.

Договор между системой и ядром — JSON-схемы в `skills/trip-planner/schema/`: `request.schema.json` (что присылает система) и `response.schema.json` (что отвечает ядро, типы `setup`, `questions`, `options`, `itinerary`, `update`, `error`).

### Сервисы и ключи

Пользователь добавляет сервисы в панели «Мои сервисы» или называет их в чате — агент сам выясняет доступ. Ключ API вводится в форму, а не в чат: система хранит его отдельно (`runtime/data/secrets/`, права 600) и передаёт ядру только как переменную окружения процесса `claude` (`PROVIDER_<ИМЯ>_KEY`). В запросе к ядру — только имя переменной. MCP-серверы пользователя подключаются к ядру автоматически на каждый вызов.

Каталог известных сервисов и способов доступа — `skills/trip-planner/providers.md`.

### API системы

| Запрос | Что делает |
|---|---|
| `POST /api/start` `{user}` | новый разговор |
| `POST /api/message` `{conversation, text, attachments?}` | сообщение пользователя → ответ ядра |
| `POST /api/choose` `{conversation, variant}` | выбрать маршрут; дальше запросы несут его как поездку в пути |
| `POST /api/event` `{conversation, event}` | событие поездки: `step_done`, `delay`, `cancelled` |
| `POST /api/providers` `{conversation, providers?}` | список сервисов; с `providers` — заменить |
| `POST /api/key` `{conversation, env, key}` | сохранить ключ сервиса |
| `GET /files/…` | календари и страницы маршрутов |

## Ограничения

- Ядро только планирует и даёт ссылки: оплачивает пользователь. Автозаказ (через Duffel) — следующий этап, см. `SYSTEM_PLAN.md`.
- Без доступа к живым источникам цены берутся с публичных страниц и помечаются как оценочные «≈».
- Полный прогон с живыми ценами, группой и поездкой по картинке ещё не сделан: в среде разработки Kiwi, Frankfurter и ЦБ были недоступны.
